# Признак режима спроса для RL-агента управления запасами

Итоговый проект по курсу «Обучение с подкреплением» (МИФИ / SkillFactory), трек 2: собственная среда.

## Вопрос

Склад одного товара, потерянные продажи, срок поставки 2 шага. Спрос переключается между спокойным
режимом N(10, 2²) и шоком N(13, 6²) по марковской цепи (средняя длина спокойного периода 25 шагов, шока 10).

Помогает ли агенту PPO явный признак режима — вероятность шока, посчитанная фильтром Гамильтона по
последним 4 значениям спроса, — если эти же 4 значения уже есть в его наблюдении? Меняет ли признак то,
как агент держит страховой запас в шоковые периоды, и снижает ли он стоимость и дефицит?

Признак — детерминированная функция наблюдения, новой информации он не добавляет. Поэтому сравнение
проверяет не «больше данных — лучше», а то, может ли агент за ограниченный бюджет сам выделить режим
из сырого спроса.

## Гипотеза (зафиксирована до основного обучения)

H1. При одинаковом бюджете (500k шагов) агент с признаком режима по сравнению с базовым агентом:

1. различает режимы: разница среднего целевого уровня S в шоковые и спокойные шаги у него больше;
2. реже допускает дефицит в шоковые шаги;
3. имеет меньшую среднюю стоимость эпизода на тестовом сценарии с тем же распределением, что при
   обучении: ожидаем снижение на 3–8 %, разница значима по критерию Уэлча по 5 seed (p < 0,05);
4. сохраняет преимущество при частых и длинных шоках (параметры шока те же, что при обучении); при более
   сильных шоках (σ = 9) преимущество может пропасть, потому что фильтр считает с неверными параметрами.

Обоснование:

- лучший постоянный уровень S — компромисс: он завышен для спокойного режима и занижен для шока. В
  пилоте (100 отдельных эпизодов) правило «два уровня S, переключение по признаку» было дешевле лучшего
  постоянного уровня на 8,6 %, а правило, знающее истинный режим, — на 18 %. Знание режима полезно;
- тот же фильтр по всей истории спроса давал почти то же (8,6 % против 8,4 % по 4 последним значениям),
  то есть 4 значений достаточно и базовый агент в принципе имеет всю нужную информацию;
- признак — нелинейная функция спроса (сравнение квадратов отклонений от средних двух режимов). Сеть
  может выучить её сама, но сигнал награды шумный: дефицит из-за заниженного уровня проявляется через
  2–3 шага и смешан со случайностью спроса. В пилотных запусках для подбора гиперпараметров базовый
  агент сходился к почти постоянному уровню.

Решающее правило: H1 подтверждена, если выполнены пункты 1–3; частично — если направление эффектов
верное, но p ≥ 0,05; опровергнута — если агент с признаком не дешевле базового.

Дополнительный вопрос (эффективность обучения): при бюджете 1,5M шагов (3 seed на условие) разрыв
должен сократиться, но не исчезнуть.

До фиксации гипотезы был один пробный запуск агента с признаком (1 seed, 400k шагов) — проверка, что
обучение работает. В отчёт он не входит. Гиперпараметры PPO выбирались по базовому агенту, чтобы не
подыгрывать гипотезе.

## План эксперимента

- Условия: `base` — наблюдение: запас на складе, 2 заказа в пути, 4 последних значения спроса;
  `regime` — то же плюс вероятность шока. Среда, награда, PPO, гиперпараметры, бюджет, seed и оценка
  одинаковые.
- Обучение: 5 seed на условие (0–4), 500k шагов, 8 параллельных сред.
- Эталоны: случайная политика; base-stock с уровнем, подобранным на спокойном режиме; лучший
  постоянный base-stock; два уровня S с переключением по тому же признаку; два уровня по истинному
  режиму (оракул, верхний ориентир). Уровни подбираются на отдельных 300 эпизодах.
- Оценка: жадная политика, 200 тестовых эпизодов на сценарий (seed 100000–100199, нигде больше не
  используются), одни и те же эпизоды для всех политик. Сценарии: как при обучении; пустой склад в
  начале шока; затоваривание (100 единиц); частые шоки; длинные шоки; сильные шоки.
- Метрики: средняя стоимость эпизода (основная), доля шагов с дефицитом (всего, в шок, в спокойные шаги),
  доля потерянного спроса, средний целевой уровень и средний запас по режимам, составляющие стоимости.

Полное описание среды (состояние, действие, награда, конец эпизода), графики и анализ — в
[`report.ipynb`](report.ipynb). Ниже — краткая сводка.

## Выводы

- H1 подтверждена **частично**. Агент с признаком различает режимы (п. 1) и дешевле базового на 6,5 %
  (п. 3), но доля дефицита в шок у него почти та же (п. 2 незначим). Преимущество сохраняется при других
  начальных состояниях, длинных и сильных шоках, но пропадает при частых шоках (п. 4 — частично).
- Механизм не тот, что ожидался: 152 из 190 у.е. выигрыша — это хранение. Агент с признаком держит меньше
  запаса в спокойные периоды, а начало шока не защищено ни у кого: шок виден только после первого высокого
  спроса, а заказ приходит через 2 шага.
- Базовый агент, хотя видит те же 4 значения спроса, сходится почти к постоянному уровню и не выделяет режим
  даже за 1,5M шагов. Готовый признак режима здесь — вопрос эффективности обучения, а не информации.
- Агент с признаком всё же хуже простой эвристики с тем же признаком (2712 против 2652): он получает около
  72 % её выигрыша над постоянным уровнем.

Ограничения, альтернативные объяснения и условия переноса — в разделе 9 ноутбука.

## Как запустить

Python 3.11. Обученные модели и результаты лежат в репозитории, поэтому ноутбук можно выполнить сразу
(шаги 1 и 6); шаги 2–5 воспроизводят всё с нуля.

```bash
# 1. окружение
python3.11 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

# 2. обучение: 2 условия x 5 seed x 500k шагов -> models/, results/curves/
python train.py --jobs 4
# 3. проверка бюджета: 2 условия x 3 seed x 1.5M шагов
python train.py --long --jobs 3
# 4. подбор уровней эвристик -> results/baselines.json
python tune_baselines.py
# 5. оценка всех политик на тестовых сценариях -> results/test_metrics.csv
python evaluate.py
# 6. отчёт
jupyter nbconvert --to notebook --execute --inplace report.ipynb
```

На Colab: клонировать репозиторий, `%cd` в него, `!pip install gymnasium==1.4.0 stable-baselines3==2.9.2`
(torch, numpy, pandas, matplotlib, scipy там уже есть), дальше те же команды с `--jobs 2`.

Seed: обучение 0–4 (500k) и 0–2 (1,5M), обучающие среды получают seed 1000·k … 1000·k + 7; валидация
(кривые обучения) 50000–50049; подбор эвристик 60000–60299; тест 100000–100199. При фиксированных seed и
одном потоке на запуск обучение детерминировано: повторный прогон дал те же кривые обучения и тестовые
метрики.

## Бюджет вычислений

Apple M1, один поток на запуск: 2,6–3,8 мин на запуск 500k и 7,8–9,3 мин на запуск 1,5M при умеренной
загрузке машины; подбор эвристик около 14 мин, оценка около 1,5 мин, ноутбук около 1 мин. Всего около
100 мин процессорного времени одного ядра. На Colab CPU (2 ядра) ориентировочно 1–2 часа (на Colab не
проверялось). Времена последнего прогона, сохранённые в `results/curves/*.csv`, больше: машина тогда была
загружена другими задачами.
